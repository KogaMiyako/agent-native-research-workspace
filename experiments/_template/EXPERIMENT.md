## 执行

运行本实验前，请提交仓库当前状态，并在下方记录确切的提交。

* **仓库：** `repos/<repo>`
* **Git 提交：** `<提交哈希>`
* **脚本目录：** `scripts/<repo>/experiments/E###-<type>-<name>/`
* **Run 目录：** `runs/<repo>/E###-<type>-<name>/`

执行顺序：

```text
register.sh
    ↓
全部 Run = pending
    ↓
检查服务器和 GPU
    ↓
Agent 生成 servers/<server>.sh
    ↓
dispatch.sh
    ↓
status.sh（按需）
    ↓
collect.sh
```

派发前必须注册全部 Run。远程服务器只执行已经注册的 Run，不得动态创建新的 Run ID。

服务器脚本中的 `GPU_QUEUES` 是任务分配的唯一来源；派发前必须确认全部当前 `pending` Run 均被分配且恰好出现一次。

### 代码版本规则

一个实验通常应对应一个有效的 Git 提交。

如果发现缺陷：

* 如果缺陷导致实验无法正确运行，且尚未产生有效结果，则修复缺陷、创建新提交，并更新上方记录的 Git 提交。实验本身保持不变。
* 如果在有效 Run 已经完成后才发现缺陷，且该缺陷可能影响实验结果，则修复缺陷、创建新提交，并启动一个新的 Experiment。不要将修正后代码产生的 Run 与原实验混在一起。

一旦产生了有效 Run，通常不应再更改与该 Experiment 关联的代码版本。

Run 注册后，runner、adapter 和配置快照也属于冻结的执行定义；这些内容变化时应注册新的 Run。
