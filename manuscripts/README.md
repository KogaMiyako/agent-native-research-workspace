# 作者稿件

此目录保存作者正在撰写的论文、图资产和需要归档的投稿版本。外部论文归 `references/`，研究知识归 `docs/research/`，实现和绘图代码归 `repos/`，原始实验输出归 `runs/`。

## 创建稿件

1. 将 `_template/` 复制为 `manuscripts/<manuscript>/`，选择简短且稳定的稿件名。
2. 填写稿件 `README.md`，明确正文入口、语言或版本定位、关联代码仓库、构建方式和实验依据。
3. 使用模板自带的 `source/`、`figures/`、`build/` 和 `release/`，将源码与依赖放到对应位置。
4. 使用 `figures/FIGURES.md` 管理图号、候选版本、采用文件和来源。

稿件名不必等于代码仓库名。同一研究可以有独立的不同语言稿或投稿稿，在各自 README 中说明关系和资源是否独立。不要把同一份源码复制到多个“当前入口”。

模板入口：[稿件 README](_template/README.md)、[图索引](_template/figures/FIGURES.md)。四个基础目录已包含在模板中；空目录使用 `.gitkeep` 保留，复制后即可使用。图资产、候选版本和具体归档目录在实际使用时创建。

## 目录与职责

```text
manuscripts/<manuscript>/
├── README.md
├── source/
├── figures/
│   ├── FIGURES.md
│   ├── F01-<topic>/
│   └── candidates/
│       └── F01-<topic>/
│           └── v001/
├── build/
└── release/
```

| 位置 | 内容与维护方式 |
| --- | --- |
| `README.md` | 当前正文入口、构建方法、代码与证据索引、归档入口；维护当前摘要，不逐次追加操作历史 |
| `source/` | 当前正文、引用库及独立构建必需的类文件、样式和配置 |
| `figures/` | 采用图、逐版候选、预览及必要的可编辑文件；不复制训练输出 |
| `build/` | 编译生成的 PDF、日志和辅助文件，默认由 Git 忽略 |
| `release/` | 需要长期保留的投稿版或阶段版本，默认可由 Git 跟踪 |

构建命令应将生成物输出到 `build/`，不要与 `source/` 混放。使用何种编辑格式、构建工具、排版引擎和期刊模板，由具体稿件决定并写入 README。

## 图的编号与文件

资产 ID 使用 `F01`、`F02`……，主题目录使用 `F01-<english-topic>`。ID 标识同一个图资产，论文 Figure 编号和 label 单独记录，不能从资产 ID 推断论文图号。

* 当前采用图：`figures/F01-<topic>/figure.pdf`。
* 候选版本：`figures/candidates/F01-<topic>/v001/figure.pdf`。
* 预览：同目录下的 `preview.png`；需要时保留 `figure.svg` 或可编辑源文件。

论文图默认交付 PDF；照片等天然位图可用 `figure.png` 等合适格式，图索引记录实际主文件。论文引用采用图的稳定路径。

同一图的配色、布局、案例或对比方式变化沿用资产 ID，新建下一版本；只有独立的新主题才分配新 ID。版本取该资产已有最大值加一，不覆盖、复用或重命名已有版本，不使用 `final2` 等临时名称代替版本号。

## 生成、采用与调整图号

### 生成候选

“画一版”“修改看看”表示生成候选。先查图索引确认资产和已有版本，再生成新版本并更新候选表，不替换采用文件或修改正文引用。

候选表应记录修改说明、生成入口、代码版本或必要指纹，以及数据或参考来源。实验图链接到实际 Experiment/Run 和输入产物；方法示意图记录方法依据或参考素材，不为其创建虚构 Run。绘图代码和原始实验数组仍分别保存在 `repos/` 与 `runs/`。

借鉴外部论文的图时，按 [参考资料规范](../references/README.md) 查看论文索引与单篇图参考记录，在本稿件图索引的来源字段链接到对应 `PAPER.md` 的图记录，并保留原图号和 PDF 页码。外部摘图仍在 `references/`，结合自己方法或数据生成的图按本目录候选规则保存。

### 采用候选

作者明确要求采用或替换时直接执行，无需重复确认：

1. 确认原采用图可以从已有候选版本恢复；若未归档，先保存为该资产的一个独立历史版本，并记录来源及已知信息。
2. 将选定候选复制到稳定采用入口，保留候选原件及原采用版本。归档旧图所用的版本号不能与其他候选冲突。
3. 更新图索引中的采用版本和稳定文件路径；若主文件格式改变，同步实际正文引用。
4. 按稿件记录的方式构建，并检查受影响图在文稿中的显示；无法执行构建时明确保留未验证项。

正文已引用同一稳定路径时，无需因候选版本变化而改写引用。讨论、生成或整理候选本身不表示采用，也不授权改写正文。

### 调整论文图号

论文重排时，同步实际图号、label 与图索引的映射。资产 ID、目录和历史版本不随论文图号改变；正文引用使用实际 label。

## 构建与归档

稿件 README 保存实际可执行的构建命令、工作目录、工具依赖和最终输出位置。候选图不放进 `build/`。

只有需要长期保留的版本才进入 `release/`，可使用日期加用途或版本号命名。归档后不覆盖已有版本。包内包含独立构建所需的正文、图片、引用库、类文件、样式和配置，不默认加入投稿表单或无关材料。

发布前在独立临时目录检查构建，确认没有依赖工作区外的绝对路径、符号链接或未打包文件。记录归档路径、来源提交或快照和实际验证情况；未检查时不能写成构建通过。最终 PDF 如需长期保留，应明确放入归档，而非仅留在被忽略的 `build/`。

## 同步与版本管理

稿件入口、构建方式或归档版本变化时更新稿件 README；图候选或采用变化时更新图索引。需要长期交接的采用、迁移或发布事件按根规则追加研究日志；普通候选试画不要求更新无关研究文档。

源码、图索引、候选、采用图和需要长期保留的发布版默认可由 Git 跟踪。`build/.gitkeep` 用于保留目录，其余编译产物默认忽略；候选迭代不应静默覆盖已保存版本。
