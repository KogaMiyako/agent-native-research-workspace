# 文档

此目录存放持久化的研究上下文和项目规范文档。

文档系统分为三层：

* 工作状态；
* 研究历史与项目状态；
* 规范研究知识。

除非信息确实无法合理归入现有规范文档，否则不要新建持久化 Markdown 文件。

## 目录结构

```text
docs/
├── README.md
├── CURRENT.md
├── RESEARCH_LOG.md
├── PROJECT_STATUS.md
├── research/
│   ├── RESEARCH_BASIS.md
│   ├── DATA_PROTOCOL.md
│   ├── BASELINE.md
│   ├── METHOD.md
│   └── EXPERIMENT_PLAN.md
└── reports/
```

## CURRENT.md

`CURRENT.md` 表示当前工作检查点。

它应回答：

* 我目前正在做什么？
* 我上次停在了哪里？
* 为什么要进行当前工作？
* 哪些任务或实验正在进行？
* 下一步应该做什么？
* 我正在等待什么，或受什么阻碍？
* 相关上下文在哪里？

`CURRENT.md` 是动态文档，每当工作状态发生显著变化时都可以重写。

常见的更新时机包括：

* 结束一次工作会话；
* 长时间暂停工作；
* 切换到另一项主要任务；
* 完成或放弃当前任务；
* 更改近期研究计划。

保持简洁。只阅读此文件就应能够恢复当前工作状态。

不要将 `CURRENT.md` 用作实验日志或长期历史记录。

## RESEARCH_LOG.md

`RESEARCH_LOG.md` 是研究过程按时间顺序排列的历史记录。

它仅允许追加。通常不应重写或删除已有历史条目。

仅记录有助于理解研究如何演进的事件，例如：

* 重要的代码或 Git 版本变化；
* 有意义的实验或实验组进展；
* 重要的实验观察；
* 结果分析结论；
* 研究方向或假设的变化；
* 实质性的方法开发；
* 影响后续工作的决策。

每个条目应保持简短，并在有用时链接到相关仓库、实验、Run、文档或提交。

不要重复记录已在其他位置保存的详细实验配置、原始日志、指标或代码变更。

---

## PROJECT_STATUS.md

`PROJECT_STATUS.md` 提供研究生命周期的简明概览。

它应反映项目在以下方面的成熟度：

* 研究基础；
* 数据与评估；
* 基线；
* 方法开发与初步验证；
* 实验计划；
* 论文就绪度。

此处不应重复详细的研究内容。
每个章节都应依据 `research/` 下对应的一份或多份规范文档进行评估；论文就绪度是对研究基础、方法和正式实验证据的汇总检查，不单独维护 `PAPER_READINESS.md`。

方法开发可以使用简明表格来跟踪已采用、测试中、已提出、已废弃及迭代中的创新点。

当新证据改变先前结论时，研究状态可以回退。

## research/

`research/` 目录包含项目的规范研究文档。

应持续维护这些文件，而不是用新建文档替代它们。

### RESEARCH_BASIS.md

记录研究背景、问题定义、实证证据、相关技术路线，以及启发拟议解决方案的文献或思路。

### DATA_PROTOCOL.md

定义实验数据与评估协议，包括基于文献的实验设置、数据集就绪状态和评估指标。

### BASELINE.md

记录基线复现、已识别的限制或改进机会，以及可能干扰可靠方法比较的因素。

### METHOD.md

记录方法开发与初步验证。

对于每个创新点，应保留：

* 动机；
* 方法流程；
* 论文风格的方法设计与公式表达；
* 初步实验证据；
* 当前结论。

实质性迭代和已废弃思路应保持可追溯。

### EXPERIMENT_PLAN.md

规划论文所需的正式实验证据。

应从最终论文的角度进行设计，包括：

* 所需的实验结果表；
* 计划制作的图和分析；
* 支撑主要主张所需的证据；
* 对应实验数据的索引。

随着实验数据产生，可以逐步填写正式结果表。

## reports/

`reports/` 是唯一允许自由创建临时文档的文档区域。

可用于存放临时或任务专用材料，例如：

* 详细分析报告；
* 阶段性总结；
* 会议材料；
* 探索性比较；
* 一次性调查笔记。

报告不属于规范研究状态。

如果报告得出了对项目持续重要的稳定结论，应将其提炼到 `research/` 下适当的规范文档、`CURRENT.md` 或 `RESEARCH_LOG.md` 中。

---

## 文档原则

使用与信息相匹配的最小持久化文档：

* 当前工作状态 → `CURRENT.md`
* 历史研究事件 → `RESEARCH_LOG.md`
* 整体研究成熟度 → `PROJECT_STATUS.md`
* 研究背景与解决方案基础 → `research/RESEARCH_BASIS.md`
* 数据与评估协议 → `research/DATA_PROTOCOL.md`
* 基线知识 → `research/BASELINE.md`
* 方法开发与初步验证 → `research/METHOD.md`
* 正式论文实验规划与结果组织 → `research/EXPERIMENT_PLAN.md`
* 临时或探索性材料 → `reports/`

当信息应归入现有文档时，不要新建规范文档。

临时说明、探索性讨论和底层执行细节无需持久保存，除非它们成为有用的长期研究上下文。
